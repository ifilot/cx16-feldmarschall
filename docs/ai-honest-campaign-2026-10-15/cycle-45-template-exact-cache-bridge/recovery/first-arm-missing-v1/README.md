# First-arm missing-game recovery

The original C45 process was confirmed terminal with external SIGTERM/exit143. Its 11 saved games were preserved, and a SQLite backup was written as `original-partial.snapshot` before any append. This extension runs only the 389 missing stable game IDs in the existing 400-game schedule. It never deletes, replaces or reruns a saved game. The original interruption logs and receipts remain in the cycle directory.

The schedule comes exclusively from the embedded, hash-verified 200-pair policy-owned setup records. The second orientation swaps participants and reverses each canonical ten-glyph row, preserving the recorded 180-degree physical rotation. Every original game is checked against its schedule before writing. All runtime files, original DOS assets/emulator and the exact OpenMP worker are extracted from existing tournament artifacts and verified against the frozen receipts; no policy is rebuilt, army generated or seed redrawn. Original created time, policy recipes, setups and move seeds remain unchanged. Only the DOS adapter receives its already-authorized opponent setup; the honest native first participant does not.

The helper is deliberately qualified here only for this direct-native/DOS recovery. Its executable-permission handling is not a general Python observer-runtime recovery guarantee. Three tests check complete stable IDs, every rotated side pair, malformed records/seed binding and rejection of a privileged or mismatched owner. The executed helper/tests are copied here, and dependency source hashes are pinned in `recovery-source-bindings.json`.

`receipt.json` records the original database and raw-game hashes, all original and missing IDs, frozen executable hashes, timing scope, final preserved-row check and completion state. Original packed-move bytes and all other original game columns must match exactly after completion. `execution_seconds` is explicitly RECOVERY-ONLY: the original interrupted execution duration is unavailable, so no full-arm time is invented or inferred from wall-clock creation time. Final aggregate analysis, native/Python replay, exact cross-arm comparator and setup audits are performed separately by the campaign owner after both arms finish.
