# Exact public-evidence cache V2 prototype

This default-off performance prototype reuses the already-computed Q12 probabilities and actor capture expectations when their public inputs are unchanged. It changes no prior, score, probability quantizer, objective, coefficient, or search limit. The new guard is `AI_TEMPLATE_PRIOR_Q24_CACHE`, which requires `AI_TEMPLATE_PRIOR_Q24`. V1 source archives, immutable IDs, build recipes and evidence remain untouched.

The cached key contains owner, all40 origin known-rank/movement bytes, a dead-origin bit per origin, and public enemy Marshal/Bomb loss counts. Bit64 is used only in the cached copy of an origin byte; the input history is unchanged. Current origin-to-square mapping is freshly exported and copied on every prepare. Before checking the key, V2 still runs the complete V1 public inventory/validity checks, compatible-template computation, background evidence calculation and remaining-rank calculation. An invalid public inventory cannot reuse a valid cache.

These inputs determine V1's quantization and gain cache exactly. Template compatibility and known counts depend only on the rank/moved origin bytes; unknown live occupancy additionally depends on dead bits. The dynamic Miner/Spy worth depends on public Bomb/Marshal losses. Current square coordinates affect only copying already-computed origin expectations onto the current board, which still happens after every fresh export. Owner is necessary when switching sides. A key hit therefore skips quantization and gain-table rebuilding only; it returns the same arrays and READY status. On a miss, the original computations run and then stamp the new key. There is no RNG use in either path.

Bank25 stores the45 additional key/validity/hit bytes. `ai_reset` explicitly calls a tiny guarded bank25 reset gateway, so arbitrary initial RAM cannot masquerade as valid cached state. This gateway restores the calling bank and uses the existing inference gateway save byte. Normal new games and resumed/custom contexts reset before the existing conservative origin-history handling. No save-format or test-state layout change is introduced: cache is an exact derived value, and a restored context is checked against its full public key before use.

## Qualification

Eleven native tests pass. They retain all six V1 numerical/public-input oracle tests and add cache dependency rejection, repeated unchanged-constraint hits, own quiet movement, opponent first movement versus subsequent same-token movement, current-square refresh, hidden-nibble invariance, disclosure, captured known origin, side change, explicit reset/poison/forget, invalid public inventory, and actual Spy/Miner worth changes when the disclosed Marshal or last Bomb falls. These are functional lifecycle tests rather than tests of arbitrary score changes.

A historical development replay compares frozen V1 against V2 on1,940 own decisions with persistent goals and actual public events. All selected moves, output RNG states, complete Flag/Bomb arrays and480 signed cache entries are exactly identical. Natural same-owner caching hits1,276times and misses664times. This measures the mechanism on that retained development history, not a validation strength effect or a universal hit rate.

The actual Commander X16 link and emulator pass48 decisions across both armies against the frozen V1 oracle, including exact output RNG, Q12, signed cache and moves. Because a two-AI demo normally alternates owners and defeats a single-owner cache, the explicitly labelled mechanical fixture restores each owner's previous ACTUAL bank25 BSS snapshot before its next call. Fresh public export and collect then decide reuse or stale-key rejection; it does not inject the current root's correct answer. The trace has19 hits and29 misses. It verifies music remains active, all bank gateways restore their caller, relocated arithmetic executes in bank25 on misses, and a996byte software-stack canary remains untouched.

Before the real initial `ai_reset`, the entire inference BSS is filled withA5 value bytes while the cache key is overwritten with the plausible matching untouched-opening key, ownerRed, loss counts0 and valid1. The real reset clears validity/hit before origin initialization; the first preparation misses and reproduces V1. This would detect a missing reset even though the stale key matches. The earlier instrumentation attempt comparing returned memory bytes with a Python list failed before gameplay; its log is preserved.

Cache-hit preparation costs130,869–171,063cycles, about16–21ms at8MHz. Misses cost7,840,487–8,833,706cycles, about0.98–1.10seconds. Whole-AI cost also includes unchanged native planning, scoring and row copying; the maximum observed whole-AI trace cost is11,431,290cycles, about1.43seconds. These are measured hit/miss fixtures, not a promise about every position. Worst-case inference is still essentially V1 plus key handling. The historical hit rate is not used to advertise an unmeasured target average.

Fresh CACHE-OFF native binary and all five custom-linked target binaries are byte-identical to frozen V1. V2's full custom link leaves MAIN66B, AI78B, mission245B, play154B and inference974B free. It still requires the isolated experimental runtime-object relocation recipe from V1; neither production builder nor installed compiler/library was changed. The actual generated-C/runtime closure proof is regenerated for V2. This is a qualified research prototype, not a CX16 production promotion.

## Files

`qualification.json` binds the owned source and source archive. `native-unit.log`, `historical-parity.json`, `banked-retention*`, `banked-decisions.json`, and the native/target cache-off parity reports contain the checks. `relocated-link.json` and its binary/generated-assembly archive freeze the actual custom build, runtime archive/object hashes and dependency proof; `cacheoff_link.py` separately rebuilds V1 from current guarded sources. `cache-probe-engine.c` adds read-only RNG/cache queries to a private native observer; it changes no model or RNG state. No saved strength games were run for V2 during this qualification.

Reproduce native checks with `PYTHONPATH=tools python3 tools/test_campaign_template_cache.py`. The historical analyzer uses the original fixed development roots and the pinned frozen V1 probe. The banked test uses the explicit `--retain-owner-cache-fixture --poison-initial-bank-bss --check-rng-output` flags. Actual emulator and ROM assets live in sibling directories, as in the V1 target qualification.
