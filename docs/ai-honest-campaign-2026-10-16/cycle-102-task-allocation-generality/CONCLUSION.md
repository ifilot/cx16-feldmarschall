# Public task allocation: honest development endpoint

The frozen task-assignment policy scored **52.60%** against the honest Missions
opponent, versus **54.69%** for its unchanged Guard control: paired difference
**−2.08 percentage points**, 95% stratified paired interval **[−5.21, +0.52]**.
This fixed development screen establishes no improvement and does not establish
a regression or equivalence. It is separate from the DOS endpoint in cycle 101.

All 192 attempts completed without engine errors. Each arm used the same 48
paired development records: eight each from the six frozen generator families.
Python and native replay verified every saved state, corpus provenance was
verified from the embedded artifacts, and each arm has a Qt6 review capture.
Both validation partitions remain unplayed.

Only four paired scores differed: one improved, three worsened, 44 tied. The
direction diagnostic is p=0.625; it is descriptive, not a mean-effect test or a
campaign-adjusted claim. Rear shells and exposed rear Flags each changed by
−6.25 points; the other four family mean scores were unchanged. These small
family samples cannot establish equivalence or a stable family regression.

The idea opens a new public target by moving one redundant capable pursuer while
preserving each original primary attacker. Coverage may have value, but removing
a second attacker can also weaken cooperative pursuit. The present data do not
justify promoting this unchanged mechanism. No coefficient, gate, layout or
policy was tuned from these outcomes. Production remains unchanged.
