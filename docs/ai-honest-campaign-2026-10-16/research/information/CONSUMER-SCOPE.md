# Scope of the current native consumer

The exact model computes all twelve ranks. The existing NativeTemplateBot
consumer exports only Flag/Bomb marginals and leaves native mobile combat
strength exchangeable. Full mobile-rank changes alone cannot affect that
consumer.

When public evidence has eliminated every source-template component, an event
about a **moved** contact therefore has no effect on the current policy's belief
packet. Proof: the contact is certainly mobile. Conditioning on any possible
mobile rank removes one mobile count, while leaving both the number of unmoved
slots U and every immobile rank count unchanged. Every other unmoved slot keeps
the same Flag and Bomb probabilities, count/U, in every conditional case.
Moved slots have zero immobile probability in every case. Averaging the cases
preserves these values exactly.

With surviving templates, the same event can still change their relative
weights and thereby influence Flag/Bomb beliefs elsewhere. An **unmoved** contact
can change its own immobile probabilities under the background alone, as the
screening packet audit demonstrates.

V1 and V2 store the first qualifying missed event until its contact is disclosed.
An inactive moved-contact event can occupy this single observation slot. That
is a declared scope limit, not incorrect conditioning or a reason to change a
frozen policy during play. A possible separate research hypothesis is to spend
the one-event memory only on observations that change the actual consumer's
packet. This needs its own prespecified selection semantics, immutable ID and
fresh cohort. It must not be folded silently into the geometry-corrected V2.
