Define and benchmark a deployment selection policy.
The existing experiments measured individual layouts. They did not establish that randomly selecting from the retained portfolio improves play.
- Compare current protected random deployment, CORNER FORTRESS alone, and a varied selection policy.
- Include the three retained evolved layouts as candidates, without assuming they improve strength.
- Choose the selection weights using development games.
- Freeze those weights before independent validation.
- Validate Normal and Hard separately, using fresh seeds, all seven layout families, the opponent league and swapped sides.
- Report overall score, capped games and performance by layout family.
Completion gate: a varied policy demonstrates a useful gain without depending on a single predictable setup. If it fails, retain the results and leave runtime deployment unchanged.

Integrate the successful deployment policy into the X16 game.
Do this only after step 1 establishes which policy deserves adoption.
- Add the selected layouts and selection logic to the deployment path.
- Preserve legal inventories, board orientation and reproducible random behavior.
- Check how much space the layout data and code require before choosing their storage location.
- Verify actual banked execution, deployment display, new-game flow and demo behavior.
- Rebuild and check the distribution and local browser package.
- Document the adopted policy and its measured limits.
Completion gate: the runtime implements the validated selection policy and passes the relevant game and memory checks.

Turn decoy and stall diagnostics into a small, actionable evaluation set.
The corpus already exists. The next task is determining which decisions are avoidable mistakes.
- Select representative examples of rear-bomb decoys, repeated quiet moves, ineffective Miner approaches and specialist losses.
- Reconstruct each position using only information available to the AI.
- Identify plausible alternative moves and explain their purpose.
- Separate unavoidable blocked positions from positions where the AI can make progress.
- Keep diagnostic examples separate from independent strength evaluation.
Completion gate: a focused set of public-information examples with clear symptoms and useful alternative decisions.

Test one mission improvement at a time.
Start with a rule for reconsidering an unproductive mission. Then investigate specialist preservation and support.
- Measure whether the assigned pieces are advancing toward their jobs.
- Reduce commitment when a mission repeatedly fails to advance.
- Reconsider suspected flag sectors when public evidence weakens or contradicts the hypothesis.
- Explore preserving a Miner when it is needed for another credible route.
- Explore escort or support assignments where an isolated specialist cannot proceed safely.
Earlier sector-memory and related prototypes failed to establish gains, so these should be new, narrowly defined experiments with explicit reasons for expecting improvement.
Completion gate: better behavior on the diagnostic set and a reliable gain against the frozen mission baseline on fresh broad-suite games. Diagnostic success alone is insufficient.

Validate each accepted mission change on X16 before promotion.
- Plan substantial additions around the mission bank; the tactical bank has only 45 bytes free.
- Check main RAM and stack headroom.
- Run concealed-rank invariance and public-information checks.
- Verify native/X16 parity with persistent state and both armies.
- Measure decision timing and bank restoration.
- Check save/load behavior if new persistent state is introduced.
Completion gate: the strength improvement fits and works on the actual target.

Establish a stronger desktop teacher before training another student.
The existing pipeline works, but global teacher strength remains unproven.
- Evaluate the current teacher’s choices against the mission policy.
- Investigate sampled-world inconsistencies and the limits of its material-focused analysis.
- Compare a stronger information-set approach with the existing teacher.
- Expand coverage to quiet strategic decisions, decoys and sparse endgames.
- Continue enforcing public-only inputs.
Completion gate: evidence that the teacher produces better decisions across a useful range of positions.

- Include accumulated-history and missing-history examples.
- Keep related positions and games in the same data split.
- Evaluate actual game strength, alongside prediction accuracy.
- Promote only after independent strength, fairness, timing and X16 checks pass.
