# AI consolidation and research extraction

Approved scope: the user's “Proceed as planned” follows the proposal to ship a
qualified version of the best honest AI and move future AI research to its own
repository. This is not another time-limited strength-search campaign.

## Required end state

1. Preserve `student-fortress-template-flag-bomb-v1-normal` and its exact source,
   recipe, observations-only contract and validation evidence as the reference.
2. Freeze a new Classic Normal shipping candidate using Fortress deployment and
   native cached Q24 inference. Numerical differences require a new immutable ID.
   Easy, Hard and optional-rule behavior retain their previous definitions.
3. Qualify same-input decisions, fresh matched DOS and honest-opponent games,
   complete X16 turns, reset/load/save behavior, audio, bank/stack integrity,
   memory limits, reproducible builds and distribution contents before promotion.
4. Make the qualified candidate the game's default Classic Normal AI. Keep a
   small versioned release package, checksums, build contract and evidence summary
   in the game. Future experiments must not grow the production tree.
5. Create `feldmarschall-ai` as a distinct repository. Move the policy registry,
   frozen source archives, experiments, training/evaluation tools, tournament
   runner, Qt6 companion, DOS adapter, datasets and detailed evidence there.
   Preserve research history and all accepted/rejected evidence; verify every
   moved file against its original Git blob before deleting its game-tree copy.
6. Keep game rules authoritative in this repository. Research consumes an exact
   pinned game-core revision and uses the existing public engine protocol. It
   must build and review portable saved matches independently of this worktree.
7. Export AI releases as portable C/model files plus an immutable identity,
   checksums, recipe and qualification evidence. The game vendors a specific
   release; it does not follow the research repository's working branch.
8. Verify the cleaned game build/tests/distribution and the extracted research
   catalog/rebuild/tournament/replay/Qt workflow. Publish the new repository if
   available credentials permit; preserve a complete local repository otherwise
   and explicitly report the publication dependency.

## Scientific boundaries

The reference's 44.33% historical DOS score and 41.87% fresh score are separate
cohorts. It is the established DOS specialist, not a universal human-play winner.
The shipping candidate is a numerical/integration port, not a tuned strategy.
Fresh validation will not be used to tune it. Whole-turn hardware qualification
cannot be inferred from deployment-only checks or desktop matches.

The existing Q24 exact cache is the starting implementation: prior checks found
identical trajectories to uncached Q24, with much cheaper cache hits. Its current
bank-25 runtime relocation is experimental and must become an explicit,
reproducible production build step with verified dependency closure.
